Why Non-Prod separately

Non-Prod แยก compartment กับ Prod เพื่อ: (1) คุม cost ได้ชัด · (2) ทดสอบ destructive operations โดยไม่กระทบ Prod · (3) RBAC แยก dev team ไม่ให้แตะ Prod · (4) สามารถ refresh data subset จาก Prod มาทดสอบได้

Compartment + VCN Setup

สร้าง compartment แยกสำหรับ Non-Prod · setup Virtual Cloud Network (VCN) + subnets

เป้าหมาย
Compartment "nonprod" + VCN 10.30.0.0/16 พร้อม subnets: public-lb · oke-nodes · oke-pods · private-data

2.1 สร้าง Compartment

oci iam compartment create \
  --compartment-id $ROOT_COMPARTMENT_OCID \
  --name $COMPARTMENT_NAME \
  --description "Non-Prod environment for AIS MMT-RFP · dev/qa/uat/staging" \
  --wait-for-state ACTIVE

export COMPARTMENT_OCID=$(oci iam compartment list \
  --compartment-id $ROOT_COMPARTMENT_OCID \
  --name $COMPARTMENT_NAME \
  --query "data[0].id" --raw-output)
echo "Compartment OCID: $COMPARTMENT_OCID"
Compartments vs Resource Groups

OCI Compartment ทำหน้าที่คล้าย Azure Resource Group แต่ยืดหยุ่นกว่า · มี hierarchy ได้ · IAM policy ผูกกับ compartment · การเก็บ tag, quota, billing แยกตาม compartment

2.2 สร้าง VCN + Subnets

SubnetCIDRTypeใช้
public-lb10.30.0.0/24PublicOCI Load Balancer
oke-nodes10.30.1.0/24PrivateOKE worker nodes
oke-pods10.30.4.0/22PrivatePod IPs (VCN-native CNI)
private-data10.30.10.0/24PrivateDB · Cache · Streaming endpoints
 
# VCN
export VCN_OCID=$(oci network vcn create \
  --compartment-id $COMPARTMENT_OCID \
  --display-name $VCN_NAME \
  --cidr-blocks '["10.30.0.0/16"]' \
  --dns-label "vcn${SUFFIX}" \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)

# Internet Gateway (สำหรับ public subnet)
export IGW_OCID=$(oci network internet-gateway create \
  --compartment-id $COMPARTMENT_OCID \
  --vcn-id $VCN_OCID \
  --is-enabled true \
  --display-name "igw-nonprod" \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)

# NAT Gateway (สำหรับ private subnet egress)
export NAT_OCID=$(oci network nat-gateway create \
  --compartment-id $COMPARTMENT_OCID \
  --vcn-id $VCN_OCID \
  --display-name "nat-nonprod" \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)

# Service Gateway (private access ไป OCI services)
export SG_OCID=$(oci network service-gateway create \
  --compartment-id $COMPARTMENT_OCID \
  --vcn-id $VCN_OCID \
  --services "[{\"serviceId\":\"$(oci network service list --query 'data[?contains(\"cidr-block\",`all-`)].id|[0]' --raw-output)\"}]" \
  --display-name "sg-nonprod" \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)
3 Gateways = 3 บทบาท

Internet Gateway = public ingress · NAT Gateway = private egress to internet · Service Gateway = private access to OCI services (Object Storage, Streaming, etc.) โดยไม่ผ่าน internet · ประหยัด egress cost

ระวัง CIDR overlap

ถ้า AIS มี VCN/VNet อื่นที่อาจ peer กับนี้ในอนาคต · เลือก CIDR 10.30.0.0/16 ที่ไม่ชนกับ Prod (10.20.0.0/16) และ AIS on-prem

✓ ตรวจสอบ
oci network vcn get --vcn-id $VCN_OCID --query "data.\"lifecycle-state\"" --raw-output
# คาดว่าได้: AVAILABLE

OCI WAF (Detection) + Load Balancer

สร้าง Load Balancer + WAF ใน Detection mode สำหรับ Non-Prod (ไม่ block traffic เพื่อ debug ง่าย)

เป้าหมาย
Public LB Fixed 10 Mbps · WAF Detection mode · public IP พร้อม route ไป OKE

3.1 Public IP + Load Balancer

export PUBLIC_SUBNET_OCID=$(oci network subnet create \
  --compartment-id $COMPARTMENT_OCID \
  --vcn-id $VCN_OCID \
  --cidr-block "10.30.0.0/24" \
  --display-name "public-lb" \
  --dns-label "publb" \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)

export LB_OCID=$(oci lb load-balancer create \
  --compartment-id $COMPARTMENT_OCID \
  --display-name "lb-nonprod-${SUFFIX}" \
  --shape-name "10Mbps" \
  --subnet-ids "[\"$PUBLIC_SUBNET_OCID\"]" \
  --is-private false \
  --wait-for-state SUCCEEDED \
  --query "data.id" --raw-output)

export LB_PUBLIC_IP=$(oci lb load-balancer get \
  --load-balancer-id $LB_OCID \
  --query "data.\"ip-addresses\"[0].\"ip-address\"" --raw-output)
echo "LB Public IP: $LB_PUBLIC_IP"
Shape "10Mbps" = Fixed, ถูกที่สุด

Non-Prod ใช้ fixed shape 10Mbps (~$10/mo) แทน flexible · ไม่ auto-scale แต่เพียงพอสำหรับ test traffic · Prod ใช้ flexible 10-8000 Mbps

3.2 OCI WAF (Detection Mode)

cat > waf-policy.json <<'EOF'
{
  "actions": [
    {"name": "Log Only", "type": "RETURN_HTTP_RESPONSE",
     "code": 200, "headers": [], "body": {"type": "STATIC_TEXT", "text": ""}}
  ],
  "requestProtection": {
    "rules": [
      {"key": "owasp-crs", "name": "OWASP CRS",
       "type": "PROTECTION", "actionName": "Log Only",
       "protectionCapabilities": [
         {"key": "920170", "version": 1},
         {"key": "942100", "version": 1},
         {"key": "941100", "version": 1}
       ]}
    ]
  }
}
EOF

export WAF_OCID=$(oci waf web-app-firewall-policy create \
  --compartment-id $COMPARTMENT_OCID \
  --display-name "waf-nonprod-${SUFFIX}" \
  --from-json file://waf-policy.json \
  --wait-for-state ACTIVE \
  --query "data.id" --raw-output)
Detection vs Prevention

Detection mode = log อย่างเดียว · ไม่ block · ให้ตัว tester reproduce attack patterns ดู logs ได้ง่าย · เปลี่ยนเป็น Prevention mode ใน Prod เพื่อ block จริง

✓ ตรวจสอบ
oci lb load-balancer get --load-balancer-id $LB_OCID \
  --query "data.{state:\"lifecycle-state\",shape:\"shape-name\",ip:\"ip-addresses\"[0].\"ip-address\"}" --output table

OKE Cluster — Non-Prod Sizing

สร้าง OKE cluster 1 AD · 1 OCPU/4GB workers · 1-3 nodes (vs Prod's 2 AD + 2 OCPU/16GB + 2-10 nodes)

เป้าหมาย
OKE cluster k8s 1.29 · single AD · auto-scale 1-3 nodes · VCN-native pod networking

4.1 สร้าง OKE Cluster

ใช้เวลา ~10 นาที

Provisioning OKE cluster ใช้เวลาประมาณ 10 นาที · ไปต้มกาแฟได้

export AD1=$(oci iam availability-domain list \
  --compartment-id $TENANCY_OCID \
  --query "data[0].name" --raw-output)

# Private subnet for OKE nodes
export NODE_SUBNET_OCID=$(oci network subnet create \
  --compartment-id $COMPARTMENT_OCID \
  --vcn-id $VCN_OCID \
  --cidr-block "10.30.1.0/24" \
  --display-name "oke-nodes" \
  --dns-label "okenodes" \
  --prohibit-public-ip-on-vnic true \
  --wait-for-state AVAILABLE \
  --query "data.id" --raw-output)

# Create OKE cluster
export OKE_OCID=$(oci ce cluster create \
  --compartment-id $COMPARTMENT_OCID \
  --name $OKE_NAME \
  --vcn-id $VCN_OCID \
  --kubernetes-version "v1.29.1" \
  --service-lb-subnet-ids "[\"$PUBLIC_SUBNET_OCID\"]" \
  --endpoint-public-ip-enabled true \
  --wait-for-state SUCCEEDED \
  --query "data.id" --raw-output)

4.2 สร้าง Node Pool (Non-Prod sizing)

oci ce node-pool create \
  --compartment-id $COMPARTMENT_OCID \
  --cluster-id $OKE_OCID \
  --name "pool-nonprod" \
  --kubernetes-version "v1.29.1" \
  --node-shape "VM.Standard.E4.Flex" \
  --node-shape-config '{"ocpus":1,"memoryInGBs":4}' \
  --node-image-id $(oci ce node-pool-options get --node-pool-option-id all \
    --query "data.sources[?contains(\"source-name\",'Oracle-Linux-8.10')].\"image-id\"|[0]" --raw-output) \
  --size 1 \
  --placement-configs "[{\"availabilityDomain\":\"$AD1\",\"subnetId\":\"$NODE_SUBNET_OCID\"}]" \
  --ssh-public-key "$SSH_PUB_KEY" \
  --wait-for-state SUCCEEDED
VM.Standard.E4.Flex

OCI's flexible shape · เลือก OCPU + memory ได้อิสระ · 1 OCPU = 2 vCPU (AMD EPYC) · Non-Prod ใช้ 1 OCPU / 4 GB ราคา ~$30/mo · Prod ใช้ 2 OCPU / 16 GB ราคา ~$90/mo

K8s Gateway API Setup

ติดตั้ง Gateway API controller (มาตรฐานใหม่แทน Ingress) สำหรับ routing traffic เข้า OKE

เป้าหมาย
Gateway API CRDs + NGINX Gateway Controller deployed · ready to route HTTP/HTTPS traffic

5.1 Install Gateway API CRDs

kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.0.0/standard-install.yaml

kubectl get crd | grep gateway.networking.k8s.io
Gateway API vs Ingress

Gateway API เป็น successor ของ Ingress · มี role-based resources (Gateway = infra · HTTPRoute = app team) · รองรับ TCP/UDP native · multi-tenant ดีกว่า · เป็น CNCF standard

5.2 Install NGINX Gateway Controller

helm repo add nginx-stable https://helm.nginx.com/stable
helm repo update

helm install nginx-gateway nginx-stable/nginx-gateway-fabric \
  -n nginx-gateway --create-namespace \
  --set nginxGateway.replicaCount=1

# 1. Delete OKE node pool first (else cluster delete fails)
oci ce node-pool list --compartment-id $COMPARTMENT_OCID \
  --query "data[].id" --raw-output | \
  xargs -I {} oci ce node-pool delete --node-pool-id {} --force

# 2. Delete OKE cluster
oci ce cluster delete --cluster-id $OKE_OCID --force --wait-for-state DELETED

# 3. Delete DB
oci psql db-system delete --db-system-id $PG_OCID --force --wait-for-state DELETED

# 5. Delete Stream Pool (cascades streams)
oci streaming admin stream-pool delete --stream-pool-id $POOL_OCID --force

# 6. Delete LB + WAF
oci lb load-balancer delete --load-balancer-id $LB_OCID --force --wait-for-state DELETED

# 7. Empty + delete buckets
for B in $(oci os bucket list --compartment-id $COMPARTMENT_OCID --query "data[].name" --raw-output); do
  oci os bucket delete --bucket-name "$B" --force --empty
done

# 8. Finally: delete compartment (cascade deletes vault etc.)
oci iam compartment delete --compartment-id $COMPARTMENT_OCID --force

echo "Teardown complete — cost stops in ~5 minutes"
